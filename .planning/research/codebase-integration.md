## D. `Psalm` class deep dive

- `ldf/src/psalm.ts` — class at line 9. Structure:
  - `value: PsalmSection[]` (each has `label?`, `value: PsalmVerse[]`).
  - `PsalmVerse` at line 180: `{ type: 'psalm-verse', number?, verse, halfverse? }`. `verse` carries the first half (typically ends with `*`); `halfverse` carries the second half.
  - Line 167: `PsalmSection` (type `'psalm-section'`, with `label?` and `value: PsalmVerse[]`). Section breaks are used for antiphon insertion points + part labels.

**Rendering path (Liturgy → user-visible psalm):**
1. `PrayService.compile` in `app/src/app/pray/pray.service.ts:82` resolves the `Liturgy` template. For `type: 'psalm'` lookups it calls `this.documents.find(...)` and similar; `Psalm` docs end up in the compiled tree.
2. The compiled doc is passed to the template `app/src/app/pray/pray.page.html:63–77` as `[doc]="doc"` on `<ldf-liturgical-document>`.
3. `<ldf-liturgical-document>` (Stencil) delegates by `type` — for `type === 'psalm'` it renders `<ldf-psalm>`.
4. **`components/src/components/psalm/psalm.tsx`** is the renderer. Key rendering loop at lines 293–392: iterates `this.filteredValue` (sections) → `section.value` (verses). For each verse it emits:
   - `<div class='verse'>` with `<ldf-string text={verse.verse}>` (line 320) — this is where pointing overlay hooks in.
   - `<br/>` then `<div class='halfverse'>` with `<ldf-string text={verse.halfverse}>` (line 343).
   - Heading, antiphon, Gloria logic around.
5. Component receives `Psalm | string` via `@Prop() doc`. Constructs `new Psalm(newDoc)` (line 38). The `docChanged` watch retriggers `filter()`.

**What `ChantPointing` hooks into:** the per-verse rendering loop at `psalm.tsx:299–378`. The existing component already has `verse.verse` and `verse.halfverse` as strings; pointing would wrap/replace `<ldf-string text={verse.verse}>` with a pointing-aware rendering. The `Psalm` object is available as `this.obj`, so `this.obj.metadata?.pointing` and `this.obj.metadata?.chant` are readable inside render without further plumbing.

**Tone skeleton placement:** per the design, `ldf-chant-notation` renders once at the top of the psalm (not per-verse). That insertion point is around `psalm.tsx:288–291` (after `headingNode()`, before antiphon/first section).

## K. `MediaSessionService` and TTS today

**`MediaSessionService` EXISTS.** `app/src/app/services/media-session.service.ts` (388 lines).
- Injectable, providedIn root.
- Wraps `@jofr/capacitor-media-session` MediaSession plugin.
- Fields: `speechPlaying: boolean`, `speechSubscription: Subscription`, tracks subdoc/utterance indices, holds `doc$`/`settings$` observables.
- API:
  - `initMediaSession(doc, settings)` — creates silent audio, sets metadata/action handlers.
  - `pauseSpeech()` / `resumeSpeech(doc, settings)` / `rewind(doc, settings)` / `fastForward(doc, settings)`.
  - `startSpeechAt(voices, doc, settings, subdoc, utterance, firstTime, loading, doc$, settings$)` — main entry; subscribes to `speechService.speakDoc(...)`.
  - `setContentEl(contentEl)` / `scrollToSubdoc(subdoc)`.
  - `destroyMediaSession()`.
- Imports `SpeechService` from `./speech.service` and `AudioService` from `../pray/audio.service`.

**`SpeechService` EXISTS.** `app/src/app/services/speech.service.ts`.
- Uses `rxjs-tts`'s `speak(...)`, plus `@capacitor-community/text-to-speech` on native.
- Direct `SpeechSynthesisUtterance` usage elsewhere: `app/src/app/pray/pray.page.ts:1127–1128` (`speechSynthesis.speak(new SpeechSynthesisUtterance(...))` for a priming voice-load call).
- `isPlaying: boolean` field, `pause()`, `resume()`, `speakDoc(voices, doc, settings, subdoc, utterance)`.

**Mutual pause with chant player:** The chant player (Phase 2 per design) should:
- Subscribe to / check `speechService.isPlaying` or `mediaSessionService.speechPlaying` and pause TTS before playing a tone (call `mediaSessionService.pauseSpeech()`).
- Conversely, `MediaSessionService.startSpeechAt` should inject a hook/cancel for any active `ChantPlayerService` playback.
- No existing abstraction for "only one audio source at a time" — a small `AudioArbiter` or mutual-exclusion via `MediaSessionService` is a net-new concern. Design names `MediaSessionService` for this role, which already handles similar coordination (silent audio unlock → speech).

**Net-new work for chant player:** new `ChantPlayerService` (WebAudio synth from `PsalmTone.playback`), new component `ldf-chant-player`. Hook into `MediaSessionService` via a new public method e.g. `mediaSessionService.pauseForChant()` / reciprocal.

- `commonprayer/utils/build-canticles.ts` — generates `canticle/*.json` from embedded data.

**No existing `chant/` subdirectory** in `commonprayer/src/`. Design calls for `commonprayer/src/chant/tones/*.json` and `commonprayer/src/chant/assignments/*.json`. Follow existing convention: one JSON file per logical unit (`commonprayer/src/chant/tones/tone-1.json`, `tone-2.json`, …, `tone-p.json`, plus `commonprayer/src/chant/assignments/st-dunstan.json`, etc.).

**Psalm JSON shape:** `commonprayer/src/liturgy/psalter/bcp1979/psalm-23.json` — wraps a `Psalm` in `{ "data": [{...}] }`. **Consequence:** pointing metadata added in `commonprayer/src/liturgy/psalter/bcp1979/psalm-23.json` must also be propagated to `app/src/offline/psalter/psalms.json` (or Firestore) for the Ionic app to see it at runtime. The "where pointing lives" design decision needs a concrete sync step.
